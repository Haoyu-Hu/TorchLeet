1.1 Byte Pair Encoding

把文本切成模型能吃的 token。

为什么

模型只吃数字。按“词”切，词表会爆炸，遇到生词（OOV）就失效；按字符切，序列又太长。BPE 取折中：高频的字符组合合成一个 token，生词也能拆成已知碎片，所以不会 OOV。

训练算法

  1. 每个词拆成字符并加结尾符 </w>（区分词尾的 “est” 和词中的 “est”），统计词频。
  2. 统计所有相邻符号对的次数，按词频加权（“low” 出现 4 次，它的每个相邻对就记 4 次）。
  3. 取最高频的对，在所有词里合并为一个新符号，记录这次 merge。
  4. 重复 N 次，词表大约增加 N 个符号。

试一试：逐步合并

要想清楚

  1. 合并之后，词的拼写变了吗？（只变切分方式，拼写不变。）
  2. 合并 (a,a) 时，在 a a a 里怎么扫？从左到右贪心，同一个字符不能被用两次。
  3. 频次相同怎么办？任选，但要有固定的 tie-break，保证结果可复现。
  4. 推理时怎么编码新词？按训练时的 merge 顺序依次应用。

工业界：GPT-2 起用 byte-level BPE，最底层符号是 256 个字节，任何语言和 emoji 都能编码。

深入一层

0. 论文原文怎么说。Sennrich 等人写道：BPE（Gage, 1994）原本是一种简单的数据压缩技术，反复把序列中最频繁的字节对替换成一个没用过的新字节；他们把它改造成词的切分算法，合并的对象是字符或字符序列。做法是：用字符表初始化符号表，把每个词表示成字符序列，外加一个特殊的词尾符号（作者说这能让翻译之后还原原来的分词），然后反复统计所有符号对，把出现次数最多的那一对替换成一个新符号。

1. 词尾符与字节级。经典做法（Sennrich 等人）从字符出发，并在每个词最后一个符号后接 </w>。参考实现 subword-nmt 里确实是这样处理的。现代大模型多用字节级 BPE：起点是 256 个字节值，因此任何文本都能编码，不再需要 <unk>。

2. 词表大小 = 基础词表 + 合并次数。例如 tiktoken 里 gpt2 编码的词表大小是 50257。Llama 2 的论文写明：分词器沿用 Llama 1，用 SentencePiece 实现的 BPE，词表 32k，所有数字都被拆成单个数字，遇到未知的 UTF-8 字符就用字节来分解。Llama 3 的论文写明：词表扩大到 128K，由 tiktoken 的 100K 个 token 加上 28K 个选定的非英语语言 token 组成。

3. 先预分词，再做 BPE。实际的分词器会先用一个正则把文本切成“词块”，BPE 只在词块内部合并，避免合并跨越单词和标点。Llama 3 的分词器基于 tiktoken，它的正则里有 \p{N}{1,3}，意思是数字最多每 3 位一组切开。

4. 训练产出的是一张有序的合并表。编码新词时，从字符（或字节）出发，每次应用“排名最靠前（最早学到）”的可合并对，直到没有可合并的为止。

5. 复杂度。像本题这样每轮重扫整个词表，总代价约是“合并次数 × 语料规模”。工业实现会维护相邻对的计数索引，只增量更新被合并影响到的那几个词。

和另外几种分词算法的区别

算法怎么选下一步
BPE总是合并出现次数最多的相邻对，结果是确定的
WordPiece合并“信息量”最大的对：合并后的词频相对于各自词频的比例
Unigram从大词表出发逐步删减；同一个词可有多种切分，取概率最高的
SentencePiece不是新算法，而是直接在原始文本上跑 BPE 或 Unigram，不假设空格分词（适合中日文）

面试常追问

  1. 词表越大越好吗？大了：嵌入矩阵和输出层变大，低频 token 训练不足。小了：序列变长，注意力和推理更贵。
  2. 为什么不直接按字符或按词切？字符太长；词表太大且有 OOV。
  3. 训练语料偏英文会怎样？其他语言的词被切得更碎，同样的内容要更多 token。
  4. 特殊 token（如句子结束符）参与合并吗？不参与，它们是单独加入词表的。

1.2 Sinusoidal 位置编码

让 Attention 知道“我是第几个”。

为什么

Attention 对输入是置换不变的：打乱 token 顺序，输出只是跟着打乱。要让模型感知顺序，就得把位置信息显式注入。

公式

PE[pos, 2i]   = sin( pos / 10000^(2i/d) )
PE[pos, 2i+1] = cos( pos / 10000^(2i/d) )

直觉

每一对维度 (2i, 2i+1) 是一根以角频率 ωi 转动的指针。i 小频率高，像秒针；i 大频率低，像时针。多根指针组合起来，每个位置就有唯一的“读数”。而且 PE[pos+k] 是 PE[pos] 的线性变换（一个旋转），所以相对位移容易学。

热力图：行是位置，列是维度

左边列（低维）变化快，右边列（高维）几乎不动。

要想清楚

  1. 频率下标 i 取 0 … d/2−1，不是原始维度下标；sin 和 cos 共用同一个 ω。
  2. 为什么用 register_buffer 而不是 nn.Parameter？（固定函数、不训练，但要随 .to(device) 移动并存入 state_dict。）
  3. 数值上 10000^(-2i/d) 常写成 exp(-2i/d · ln 10000)，更稳。
  4. forward 只看 x.shape[1]，返回前 seq_len 行，形状 (1, seq_len, d)，加法由调用方完成。

深入一层

0. 论文原文怎么说。原文写道：每个维度对应一条正弦曲线，波长构成从 2π 到 10000·2π 的几何级数；作者也试过学习式位置嵌入，发现两者结果几乎相同（论文表 3 的 (E) 行）；选正弦版本，是因为它可能让模型外推到比训练时更长的序列。

1. 波长。第 i 对的角频率是 ω_i = 10000^(−2i/d)，波长是 2π/ω_i = 2π·10000^(2i/d)。i=0 时约 6.28 个位置（最快），i 接近 d/2 时接近 2π·10000（最慢）。

2. 相对位移就是旋转。由和角公式可得：

[ sin((p+k)ω) ]   [  cos kω   sin kω ] [ sin pω ]
[ cos((p+k)ω) ] = [ −sin kω   cos kω ] [ cos pω ]

所以 PE(p+k) 是 PE(p) 按位移 k 做一次与 p 无关的线性变换，模型有机会学到“往后 k 个位置”的操作。

3. 两种常见的排布。论文公式是 (2i, 2i+1) 交错排列，Annotated Transformer 的实现就是 pe[:, 0::2]=sin、pe[:, 1::2]=cos。而 Tensor2Tensor 的实现把所有 sin 放前半、所有 cos 放后半（它的文档写的是“concatenated in the channels dimension”）。两者只差维度的排列，但要对齐已有权重时必须用同一种。本题的判题按交错排列检查。

4. 怎么用。Annotated Transformer 里，词嵌入先乘 sqrt(d_model)，再与位置编码相加，然后做 dropout。位置编码的取值在 [−1, 1]，乘上 sqrt(d_model) 能让词嵌入的量级不被它淹没。

5. 数值写法。实现里常用 exp(−(2i/d)·ln 10000) 来算频率，而不是直接算 10000 的幂。

局限与替代

  • 学习式位置嵌入：每个位置一个可训练向量，最大长度固定，不能直接外推。
  • RoPE（见 1.3）：不再把位置“加”到输入上，而是旋转 q 和 k。
  • ALiBi：在 softmax 之前，给 QKᵀ 加一个与相对距离成比例的负偏置。Hugging Face 的优化指南提到，它在不做额外处理时比 RoPE 更容易外推到更长的输入。

面试常追问

  1. 为什么不直接用位置下标 pos 当特征？它无界，量级随位置增长，会压过词嵌入。
  2. 为什么不用 one-hot？维度等于最大长度，且不同位置之间没有“远近”的结构。
  3. 10000 是怎么来的？它是个经验超参，决定最慢那一对的波长。
  4. 为什么要 sin 和 cos 成对？由和角公式，sin((p+k)ω) 里同时需要 sin pω 和 cos pω。只用 sin，就无法把位移写成与位置无关的线性变换。

1.3 RoPE 旋转位置编码

LLaMA、Mistral、Qwen 都在用。

为什么

绝对位置编码是“加”在输入上的，注意力分数里相对距离不明显，长度外推也差。RoPE 改为旋转 q 和 k，使 qm·kn 只依赖相对距离 m−n。

数学

把向量两两配对看作二维平面上的点，位置 m 处整体转 mθ 角：

[x1']   [cos mθ  −sin mθ] [x1]
[x2'] = [sin mθ   cos mθ] [x2]

(R_m q) · (R_n k) = q · R_{n−m} k      ← 只剩相对位移

实现的关键恒等式（half 配对）

q' = q * cos + rotate_half(q) * sin
rotate_half([x1, x2]) = [−x2, x1]     # 最后一维切成两半
  • θi = 10000^(−2i/d)，和 sinusoidal 同一套频率；cos/sin 表按位置预先算好并缓存。
  • 只作用在 q 和 k，不作用在 v。
  • cos/sin 形状要能广播到 (batch, heads, seq, head_dim)。

试一试：旋转一个二维向量

三根向量长度相同；高频维度转得快，低频维度转得慢。长度不变，只有方向变。

要想清楚

  1. 为什么旋转不改变向量长度？（正交变换，所以 attention 的数值尺度不受影响。）
  2. rotate_half 连用两次得到什么？（−x，判题器会检查。）
  3. cos=1、sin=0 时应当什么都不变；cos=0、sin=1 时结果恰为 rotate_half(x)。

深入一层

0. 论文原文怎么说。RoFormer 的摘要列出 RoPE 的几个性质：序列长度可灵活变化；token 之间的依赖随相对距离增大而衰减；能给线性自注意力配上相对位置编码。

1. 频率。第 i 对用 θ_i = base^(−2i/d)，位置 m 处转 m·θ_i。Llama 3 的论文把 RoPE 的基频设为 θ = 500,000，并说明这样能更好地支持更长的上下文（它引用的先前工作表明该值对 32,768 以内的上下文有效）。Llama 3 官方仓库里 precompute_freqs_cis 的写法是 1 / (theta ** (arange(0, dim, 2)[:dim//2] / dim))，函数默认 theta 是 10000，而 ModelArgs.rope_theta 设为 500000。最长波长约为 2π·base，所以 base 越大，低频那几对转得越慢。

2. 为什么只依赖相对距离。把每一对看作复数，旋转就是乘 e^{imθ}：

(q·e^{imθ}) · conj(k·e^{inθ})  →  Re( q·conj(k)·e^{i(m−n)θ} )

结果里只剩 m−n。

3. 两种配对方式，不能混用。Meta 的原始实现把相邻两维 (x₀,x₁)、(x₂,x₃)… 当成复数（view_as_complex(x.reshape(…, −1, 2))）。Hugging Face 的实现用 rotate_half，把前半和后半配对。两者只差维度排列，但 q/k 的权重必须与所用配对方式一致，不能直接互换。本题用的是 rotate_half 这一种。

4. 只作用在 q 和 k。位置信息要进入的是注意力分数 q·k，v 只负责被加权求和，不需要旋转。

5. 精度。Llama 3 仓库在旋转前先把 q、k 转成 float32，算完再转回原精度。

6. 与 KV cache 配合。缓存里存的是旋转之后的 K，所以新 token 的位置编号必须是缓存当前的长度，不能从 0 开始。

长度外推

Hugging Face 的优化指南指出：RoPE 若保持训练时的 θ，在远长于训练长度的输入上效果会变差，社区提出了若干办法来适配更长的输入。常被提到的做法有：位置插值（Position Interpolation，摘要写明可把 LLaMA 模型的上下文窗口扩展到最长 32768，微调在 1000 步以内），以及 YaRN（摘要写明相比之前的方法少用 10 倍的 token、少 2.5 倍的训练步数）。另外，把 base 调大（如上面的 500000）也是在拉长最慢那几对的波长。

  2. RoPE 有可训练参数吗？没有，cos/sin 表由位置和 base 决定。
  3. RoPE 能和线性注意力一起用吗？RoFormer 的说明里提到可以。
  4. 训练长度 4k，推理给 32k 会怎样？超出训练长度的旋转角没见过，效果会变差，需要插值类方法或继续训练。

1.4 RMSNorm

更轻的归一化，现代大模型的默认选择。

为什么

深层网络需要归一化来稳定激活。LayerNorm = 减均值 + 除标准差。RMSNorm 去掉“减均值”这一步，效果几乎不变，却少一次 reduce，更快。LLaMA 等模型全面采用。

公式

RMSNorm(x) = x / sqrt( mean(x², dim=-1) + eps ) · γ
  • 沿最后一维（特征维）计算；γ 形状 (dim,)，初始化为 1，可学习。
  • eps 防止全零输入除以 0。

对比 LayerNorm

LayerNormRMSNorm
减均值是否
分母标准差均方根
可学习参数γ 和 β只有 γ
输出均值≈ β不为 0

要想清楚

  1. keepdim=True 为什么必要？（让 (…,1) 能广播回 (…,dim)。）
  2. 输出的均方根大约是多少？（γ=1 时约为 1。）
  3. fp16/bf16 下通常先转 float32 算 RMS 再转回，为什么？（平方后容易溢出或丢精度。）

深入一层

0. 论文原文怎么说。作者假设：LayerNorm 的成功主要靠“重新缩放不变性”，而不是“重新居中不变性”。于是提出 RMSNorm，只按均方根（RMS）归一化，让模型具有重新缩放不变性。摘要写明它的效果与 LayerNorm 相当，但运行时间减少 7%～64%（不同模型上的幅度不同）。

LayerNorm(x) = (x − mean) / sqrt(var + eps) · γ + β       参数 2d 个
RMSNorm(x)   =  x / sqrt(mean(x²) + eps) · γ              参数 d 个

1. 工业实现长什么样。Hugging Face 的 LlamaRMSNorm：先把输入转成 float32，算 x² 的均值，乘 rsqrt(var + eps)，再转回输入精度，最后乘 weight。它的 eps 默认是 1e-6（本题 notebook 默认 1e-8）。

2. 放在哪。Llama 的每个解码层里有两个 RMSNorm：input_layernorm 在注意力之前，post_attention_layernorm 在 MLP 之前，整个模型最后还有一个。这种“先归一化、再进子层”的写法叫 Pre-Norm。

3. 为什么更快。少一次沿特征维的均值计算，也没有 β 偏置。RMSNorm 作者的仓库说明里提到：LayerNorm 会在每个运行步骤上带来额外的计算开销，抵消了一部分它带来的训练稳定性收益。

4. 直觉。它只“重新缩放”，不“重新居中”：保持向量方向不变，把均方根固定到 1（γ=1 时）。

5. 数值。平方运算在 fp16/bf16 下容易溢出或丢精度，所以先转 float32。

面试常追问

  1. 对输入整体加一个常数，输出变吗？LayerNorm 不变（它先减均值），RMSNorm 会变。
  2. 对输入整体乘一个常数呢？两者在忽略 eps 时都基本不变。
  3. 为什么一个模型里要放那么多归一化？稳定每一层的激活量级，让深层网络可训练。
  4. RMSNorm 输出的均值是 0 吗？不是，它没有居中。

1.5 Scaled Dot-Product Attention

第 1 节的终点，也是后面所有内容的地基。

直觉

q 是“我在找什么”，k 是“我有什么标签”，v 是“我的内容”。q·k 越大越相关，softmax 把它变成权重，再对 v 加权平均。

公式与形状

Attention(Q,K,V) = softmax( Q Kᵀ / sqrt(d_k) ) V

Q:(…,Tq,d)  K:(…,Tk,d)  V:(…,Tk,dv)
分数 (…,Tq,Tk)  →  输出 (…,Tq,dv)

试一试：缩放的作用

随机 q、k 的点积方差等于 d_k。不缩放（上）softmax 随 d_k 增大趋于 one-hot，梯度消失；缩放后（下）保持平滑。

要想清楚

  1. 为什么除以 sqrt(d_k)？设 q、k 各分量均值 0、方差 1，则 q·k 的方差为 d_k；除以 sqrt(d_k) 让方差回到 1。
  2. Mask 必须在 softmax 之前把屏蔽位置设为 −inf。softmax 之后再乘 0，每行的和就不是 1 了。
  3. 因果 mask 是下三角：token t 只能看 ≤ t 的位置。
  4. softmax 沿哪一维？沿 Tk（最后一维），每个 query 对所有 key 归一。

约定：判题器的 mask 是布尔型，True 表示保留、False 表示屏蔽。返回值是 (output, attention_weights)。禁止调用 F.scaled_dot_product_attention。

深入一层

1. 为什么除以 sqrt(d_k)。论文原文就是这样解释的：点积变大会把 softmax 推到梯度极小的区域，所以要把点积除以 √d_k；脚注里给出推导：假设 q、k 的分量是均值 0、方差 1 的独立随机变量，那么 q·k 的均值为 0、方差为 d_k。Annotated Transformer 里逐字复述了论文的解释：对于较大的 d_k，点积的量级会变大，把 softmax 推到梯度极小的区域；要看出点积为什么变大，假设 q 和 k 的各分量是独立随机变量、均值 0、方差 1，那么 q·k 的方差是 d_k。它还提到，不缩放的点积注意力在 d_k 较大时不如加性注意力。

2. 代价。分数矩阵是 T×T（每个头一份），时间 O(T²·d)，显存 O(T²)。序列越长，这块越先成为瓶颈。

3. 精度。Hugging Face 的 Llama 实现里，softmax 用 float32 算，再转回 q 的精度。

4. FlashAttention。它不把 QKᵀ 整个算出来，而是分块计算，同时维护 softmax 的归一化统计量。输出与标准注意力数值上一致，显存随序列长度线性增长。它的 FLOPs 反而更多，但因为大幅减少了对慢速显存（HBM）的读写，实际更快。FlashAttention 论文的摘要把它称为“IO 感知的精确注意力算法”：用分块（tiling）减少 GPU 高带宽显存与片上 SRAM 之间的读写次数，并分析了它的 IO 复杂度，证明访问 HBM 的次数比标准注意力更少。摘要报告：相对 MLPerf 1.1 的训练速度记录，BERT-large（序列长度 512）端到端提速 15%；GPT-2（序列长度 1K）快 3 倍。

mask 的几个坑

  • 屏蔽要在 softmax 之前设为 −inf。
  • 如果某一整行都被屏蔽，softmax 的输入全是 −inf，结果是 NaN。做 padding mask 时要留意。
  • padding mask 和因果 mask 要做“并”（任何一个屏蔽就屏蔽）。
  • 各个库对布尔 mask 的约定不同：本仓库是 True=保留。torch.nn.MultiheadAttention 的布尔 attn_mask 则是 True=不允许注意。接别人的 API 时先看文档。

面试常追问

  1. 为什么用点积而不是加性注意力？点积可以用高度优化的矩阵乘法实现，更快更省空间（缩放之后质量也不差）。
  2. 缩放可以怎么理解？相当于给 softmax 加了一个与 d_k 有关的温度。
  3. 自注意力和交叉注意力的区别？q 与 k、v 是否来自同一序列。
  4. 注意力权重每行加起来是多少？1。被屏蔽的位置是 0。

  • 已核对Hugging Face：modeling_llama.py （softmax 在 float32 下计算）

2.1 Multi-Head Attention

让同一层同时关注几种不同的关系。

为什么

单头注意力每个位置只产生一个注意力分布。但一句话里同时存在多种关系：语法上的主谓、指代、邻近词、远处的呼应。多头把表示拆成几个子空间，每个头各算一套注意力，最后拼起来，让不同的头去学不同的模式。

总计算量几乎不变：d_head = d_model / h，h 个头加起来的宽度还是 d_model。

公式

Q = X·W_Q    K = X·W_K    V = X·W_V               各是 (B, T, d_model)
拆头:  (B, T, d_model) → (B, T, h, d_head) → (B, h, T, d_head)
每个头: softmax( Q Kᵀ / sqrt(d_head) ) V            分数 (B, h, T, T)
合头:  (B, h, T, d_head) → (B, T, h, d_head) → (B, T, d_model)
输出:  concat(heads) · W_O

2.2 Grouped Query Attention

  
用更少的 K/V 头换推理时的显存和带宽。

  
为什么

  
大模型推理时的瓶颈常常是读写 KV cache，而不是算力。cache 的大小与 K/V 头数成正比。GQA 保留全部 Q 头，但让若干个 Q 头共享同一组 K/V，把 cache 缩小到原来的 g/h。

Q 投影到 h · d_head；K、V 只投影到 g · d_head      ← 节省就发生在这里

之后和普通多头注意力完全一样

深入一层

  
1. 从 MQA 到 GQA。MQA 论文的摘要写道：增量推理很慢，因为要反复加载很大的 keys 和 values 张量，受限于内存带宽；MQA 让 K/V 在所有头之间共享，大幅缩小这两个张量。GQA 论文的摘要则指出：MQA 可能带来质量下降，而且为了更快推理单独训练一个模型也不一定划算。所以它 (1) 提出把已有的多头检查点用原始预训练算力的 5% 做 uptraining（继续训练），转换成 MQA 模型；(2) 提出 GQA，用介于 1 和 query 头数之间的 K/V 头数。结论是：uptrain 过的 GQA 质量接近 MHA，速度与 MQA 相当。转换时，各头的 K/V 投影矩阵对组内的头做 mean pooling（论文图 1）。

2 · 层数 · g · d_head · 序列长度 · batch · 每元素字节数

  
g 从 h 降到 g，cache 就缩小到原来的 g/h。

  
3. 省的是带宽，不只是容量。解码时每步都要把整个 KV cache 从显存读一遍，带宽常常是瓶颈（Hugging Face 的指南在讲 MQA 时说得很清楚）。缩小 cache 同时减少了每步要读的数据。

2.3 KV Cache

  
自回归生成时不要重复算已经算过的东西。

  
为什么

  
生成第 t 个 token 时，前 t−1 个 token 的 K 和 V 和上一步完全一样。不缓存的话，每一步都把整段前缀重新投影一遍。KV cache 把它们存下来，每步只为新 token 计算 Q、K、V，再把新的 K、V 追加进缓存。

  
两个阶段

  
    
    
  • 预填充（prefill）：一次处理整个提示词，带因果 mask，同时把所有 K/V 填进缓存。算力密集。
    • 
    
  • 解码（decode）：每步只输入 1 个 token，读取整个缓存。带宽密集，这就是 GQA 要省的东西。

实现要点


缓存形状: (batch, heads, seq_len, d_head)
update(new_k, new_v): 沿 dim=2 拼接，返回完整的 K、V
解码时: x 是 (B, 1, d_model) → 只算新 token 的 Q/K/V → update → 对完整 K/V 做注意力

要想清楚

  
    
    
  1. 正确性标准是什么？逐 token 用缓存生成的输出，必须等于对整段序列一次性带因果 mask 计算的输出。判题就检查这一条。
    2. 
    
  2. 用 RoPE 时，新 token 的位置编号是多少？是缓存当前长度。位置偏移弄错，结果会悄悄变差。
    3. 
    
  3. 缓存里放的是旋转之后的 K，还是旋转之前的？通常放旋转之后的，因为它的位置已经固定。
    4. 
    
  4. torch.cat 每步都会复制整个缓存，总拷贝量是 O(N²)。更好的做法是预分配最大长度的缓冲区，再往里写。
    5. 
    
  5. 显存：2 · 层数 · K/V头数 · d_head · 序列长度 · batch · 每元素字节。长上下文和大 batch 时，缓存比权重还大。
    6. 
    
  6. 服务端怎么管理缓存？分页（PagedAttention）、前缀复用、滑动窗口（见 2.4）。
    7. 
  

  
深入一层

  
1. 好处有两个。Hugging Face 的指南总结得很准：计算量减少（QKᵀ 退化成 q_c Kᵀ，q_c 是当前 token 的查询向量）；峰值显存随生成长度线性增长，而不是二次增长。

  
2. 输出一致，但不一定逐位相同。同一份指南里有个提示：用缓存后输出可能略有不同，这是矩阵乘法 kernel 自身的性质。所以本题的判题用 allclose（容差 1e-5），而不是逐位相等。

  
3. 估算大小。指南里的例子：缓存里的浮点数个数是“2 × 序列长度 × 头数 × 头维度 × 层数”。对 bigcode/octocoder 在序列长度 16000 时约 78.6 亿个，fp16 下约 15 GB，大约是模型权重的一半。

  
vLLM 论文给了一个更权威的例子：对 13B 参数的 OPT 模型，单个 token 的 KV cache 是 2（K 和 V）× 5120（隐状态维度）× 40（层数）× 2（fp16 的字节数） = 800 KB；OPT 最多生成 2048 个 token，所以一个请求的 KV cache 最多可达 1.6 GB。显存只有几十 GB，即使全部给 KV cache，也只能同时容纳几十个请求。

  
再来一个自己能心算的例子，假设一个 32 层、32 个 K/V 头、d_head=128、fp16 的模型：


每个 token：2 × 32 × 32 × 128 × 2 字节 = 524,288 字节 = 512 KB
序列 4096：512 KB × 4096 = 2 GiB          （batch=1）
改成 8 个 K/V 头（GQA）：每个 token 128 KB，同样序列 0.5 GiB

  
4. 缓存有几种形态。Hugging Face 的 KV cache 文档列出：动态缓存（默认，随长度增长）、静态缓存（预先分配好最大长度，固定大小，便于 torch.compile 这类即时编译优化）、量化缓存（占用更少显存）、把缓存卸载到 CPU（省显存、会变慢）。对使用滑动窗口的模型（如 Mistral），缓存在达到窗口大小后不再增长。

  
5. 多轮对话。聊天场景下，把上一轮的缓存继续用下去，只需处理新增的那段提示，不用重新编码全部历史。

  
6. 显存管理。vLLM 论文指出，现有系统要预先按最大长度为每个请求预留一整块连续显存，既造成内部浪费，也产生外部碎片：它们的 profiling 显示，KV cache 显存里只有 20.4%–38.2% 真正用来存放 token 的状态。PagedAttention 借鉴操作系统的分页，把 KV cache 切成块来管理，目标是几乎零浪费，并允许在请求之间共享 KV cache。论文报告在相同延迟水平下，吞吐比 FasterTransformer、Orca 等最先进系统提高 2–4 倍。

  
实现时容易踩的坑

  
    
    
  • 位置：用 RoPE 时，新 token 的位置编号 = 缓存当前长度（见 1.3）。
    • 
    
  • 批量：一个 batch 内各序列长度不同，需要 padding 并对齐；beam search 还需要按选中的路径重新排列缓存。
    • 
    
  • 拼接：每步 torch.cat 都会复制整个缓存。静态缓存的思路是预分配，再原地写入。
    • 
    
  • 预填充 (prefill) 和解码 (decode) 的瓶颈不同：前者一次处理很多 token，偏计算密集；后者每步一个 token，偏带宽密集。

2.4 Sliding Window Attention

  
长序列下，让每个 token 只看附近的 w 个位置。

  
为什么

  
完整注意力的计算和显存是 O(n²)，序列一长就撑不住。滑动窗口让 token i 只看 [i−w, i+w]，复杂度降到 O(n·w)。Mistral、Longformer 都用这个思路。

  
试一试：窗口和感受野

  

    

      
      
      

    
    

  

  
横轴是被看的位置 j，纵轴是提问的位置 i，实心格是允许的注意力。

  
实现要点


距离矩阵  |i − j|            i: (n,1)  j: (1,n)  → (n, n)
mask = (距离 <= w)             布尔，True = 允许
scores.masked_fill(~mask, −inf)   在 softmax 之前
w >= n 时什么都没屏蔽，必须与 full_attention 完全相同

  
要想清楚

  
    
    
  1. 只看附近，会不会丢掉远处信息？一层只看 w，但 L 层叠起来，信息最远可以传播 L·w。上面的演示会算出来。
    2. 
    
  2. 为什么这道题的 mask 是对称的？这里是双向版本。Mistral 是因果 + 窗口：i−w ≤ j ≤ i。勾选“因果”就是它。
    3. 
    
  3. 用 mask 实现仍然先算了完整的 n×n 分数，只是把大部分丢掉，并没有真省算力。要真省，需要 unfold 之类的分块实现，这是题目里的加分项。
    4. 
    
  4. 和 KV cache 的关系？解码时只需保留最近 w 个 K/V，缓存大小从 O(n) 变成 O(w)。用环形缓冲区实现。
    5. 
    
  5. 窗口的代价？超出窗口的精确细节要靠层数传递，或者再配少量全局注意力的 token。
    6. 
  

  
深入一层

  
1. 滑动窗口 + 全局 token。Hugging Face 对 Longformer 的描述：它把局部窗口注意力与任务相关的全局注意力结合起来，计算随序列长度线性增长，因此能处理几千 token 的文档。

  
2. Mistral 的做法。Mistral 7B 论文的架构表：window_size=4096、context_len=8192、32 层。论文说，第 k 层位置 i 的隐状态只关注上一层位置在 i−W 到 i 之间的隐状态；递归地看，它最远能访问输入层上 W×k 个 token 之外的信息。MistralConfig 里 sliding_window 的默认值也是 4096。

  
3. 环形缓冲区 (rolling buffer)。论文描述：固定的注意力跨度意味着缓存大小可以固定为 W；位置 i 的 K/V 存放在缓存的 i mod W 位置，超出后旧的被覆盖。mistral-inference 的缓存代码里有 position = seqlen % cache.shape[0]：第 i 个 token 的 K/V 写在位置 i mod W，旧的被覆盖。缓存大小因此固定为 W，不随序列增长。同一份代码里 get_cache_sizes 还支持给每一层设不同的窗口（整数，或一个按层重复的列表，列表里 None 表示该层用完整长度），也就是“有的层用窗口，有的层看全部”。

  
4. 感受野会逐层放大。单层最远只看 w，但 L 层叠起来，信息最多可传播 L·w（因果窗口）。W=4096、32 层时，4096 × 32 = 131,072；Mistral 论文也给出同样的估计：理论上的注意力跨度约 131K 个 token。这只是传播的理论上界，实际有效范围更小，远处信息要经过多层逐步传递。论文还说，序列长度 16K、W=4096 时，对 FlashAttention 和 xFormers 的改动让速度比普通注意力基线快 2 倍。

  
5. 掩码实现与真正省算力的区别。本题的主体用掩码实现：先算完整的 n×n 分数，再屏蔽。这样只省了“有效的格数”，并没有省实际的计算与显存。要真正省，需要分块或 unfold（题目里的加分项）。

  
6. 保留“开头”的变体。StreamingLLM 的摘要写道：只缓存最近 KV 的窗口注意力，在文本长度超过缓存大小时会失效；他们观察到“attention sink”现象：保留最初几个 token 的 KV，就能大幅恢复窗口注意力的表现，因为模型会把很强的注意力分数投向最初的 token，即使它们语义上并不重要。基于此，StreamingLLM 让用有限窗口训练的模型无需微调就能处理很长的序列（摘要称可达 400 万 token 以上）。

  
7. 预填充与分块。Mistral 论文还提到：提示很长时，可以把它切成小块，逐块预填充缓存，并取窗口大小作为块大小；每一块要对“缓存”和“本块”两部分做注意力。

  
面试常追问

  
    
    
  1. 窗口注意力会丢掉远处信息吗？单层会，多层叠加后信息可以逐层传递，但精确的远距离细节依然会损失。
    2. 
    
  2. 和 KV cache 的关系？解码时只需保留最近 W 个 K/V，缓存是 O(W)，而不是 O(n)。
    3. 
    
  3. 窗口注意力和稀疏注意力的区别？窗口是稀疏模式的一种（局部带状）；还有全局 token、跨步（dilated）等其他模式。
    4. 
    
  4. 窗口大小怎么选？越大越接近完整注意力，代价线性增加；要和任务所需的依赖距离匹配。
    5.

3.1 Llama 风格解码器：整体架构

  
把前两节的零件拼成一个能说话的语言模型。

  
全貌


token id          (B, T)
 → Embedding      (V, d)                          → (B, T, d)
 → 重复 N 次的解码层：
       x ← x + Attention( RMSNorm(x) )            RoPE + GQA，因果 mask
       x ← x + MLP( RMSNorm(x) )                  SwiGLU
 → RMSNorm
 → lm_head        (d → V)，常与 Embedding 共享权重   → logits (B, T, V)
 → 交叉熵：第 t 个位置预测第 t+1 个 token

  
这条主干叫“残差流”：每个子层只往 x 里加一个增量，原来的 x 一直直通到底。

  
相对原始 Transformer 的三处改动

  
Llama 论文逐条列出了它做的改动，其他同类模型基本沿用：

  
    
    
  • 预归一化（Pre-normalization）：不是归一化每个子层的输出，而是归一化每个子层的输入，用的是 RMSNorm（1.4）。
    • 
    
  • SwiGLU 激活：用 SwiGLU 取代 ReLU，隐藏维度用 (2/3)·4d，而不是 PaLM 里的 4d。
    • 
    
  • 旋转位置编码（RoPE）：去掉绝对位置嵌入，改为在网络的每一层加入 RoPE（1.3）。
    • 
  

  
SwiGLU 是什么

  
Shazeer 的 GLU 变体论文里，Transformer 的前馈层写成


FFN_SwiGLU(x) = ( Swish₁(x·W) ⊗ (x·V) ) · W₂          Swish₁(z) = z·σ(z)，也叫 SiLU

  
它有三个权重矩阵，而原来的前馈层只有两个。为了让计算量保持不变，论文把隐藏维度 d_ff 缩小到原来的 2/3；它沿用 T5 的做法，不加偏置。Hugging Face 的 Llama 实现是 down_proj( silu(gate_proj(x)) * up_proj(x) )；Meta 官方实现里的隐藏维度是 int(2 * hidden_dim / 3)，再向上取整到 multiple_of 的倍数。

  
一层的代码结构

  
Meta 官方实现的 TransformerBlock.forward 正是这两行：


h   = x + attention( attention_norm(x), ... )
out = h + feed_forward( ffn_norm(h) )

  
权重共享（tied embeddings）

  
输入嵌入矩阵 E（V×d）把 token 变成向量，输出层 lm_head 把向量变回 V 维 logits。Press 和 Wolf 的论文指出，输出层这个矩阵本身就是一个有效的词嵌入，并建议训练语言模型时把输入嵌入和输出嵌入绑在一起。好处是省掉 V·d 个参数。SmolLM2-1.7B 的配置表里写明“Tied embedding: Yes”；而 Hugging Face 的 LlamaConfig 里 tie_word_embeddings 默认是 False，可见这是各个模型自己的选择。

论文还写明：SmolLM2-135M 和 360M 与 1.7B 的架构相同，但使用了分组查询注意力（GQA，见 2.2）。

注意力   q: d·(h·dh)    k、v: 各 d·(g·dh)    o: (h·dh)·d

训练与推理

  
    
    
  • 训练：整段序列一次送入，所有位置并行算 next-token 损失（因果 mask 保证不泄漏未来）。若输出接近均匀分布，损失约为 ln V；V=49,152 时是 10.80（我的算术）。
    • 
    
  • 推理：一个 token 一个 token 地生成。朴素写法每步重算整段（3.3 就这样写），用 KV cache（2.3）可以只算新 token。
    • 
    
  • 训练算力估算：Kaplan 等人估计每个训练 token 约需 6N 次浮点运算（前向约 2N，反向约是前向的两倍）；Chinchilla 论文也用 FLOPs(N, D) ≈ 6ND，N 是参数量，D 是训练 token 数。
    • 
  

  
要想清楚

  
    
    
  1. 为什么用 Pre-Norm 而不是 Post-Norm？Llama 论文给出的理由是提高训练稳定性。残差流直通也让很深的网络更容易训练。
    2. 
    
  2. SwiGLU 为什么要把隐藏维度缩到 2/3？它有 3 个矩阵而不是 2 个，缩小后总参数量和计算量才与原来的 4d 前馈层相当。
    3. 
    
  3. RoPE 为什么只出现在注意力里，而不是加在输入嵌入上？它作用于 q 和 k，让分数只依赖相对位置（1.3）。
    4. 
    
  4. 共享嵌入有什么代价？输入和输出共用同一个矩阵，二者的需求不完全一致；小模型里它占总参数的比例大，省得更多（本例约 5.9%）。
    5. 
    
  5. decoder-only 和 encoder-decoder 的区别？前者只有因果自注意力的堆叠，生成时把已生成的文本接在提示后面继续；后者多一个编码器和交叉注意力。
    6.

3.2 实现 RoPE + GQA 注意力块

  
SmolLM 里最复杂的零件：前几节学的东西在这里合到一起。

  
目标

  
把 RoPE（1.3）、GQA（2.2）、带因果 mask 的缩放点积注意力（1.5）装进同一个模块 RopeAttention。题目来自仓库的 smollm，判题有 12 项检查。

  
五个零件

  

    
零件做什么最容易错的地方

    
rotate_half最后一维切两半，返回 (−x₂, x₁)切分的位置；连用两次必须得到 −x

    
apply_rotary_pos_embq' = q·cos + rotate_half(q)·sin；k 同理cos/sin 要先补出 head 维才能广播；cos=1、sin=0 时必须是恒等

    
repeat_kv把 g 个 K/V 头复制成 h 个第 i 个新头必须是第 i // n_rep 个旧头，不是整体平铺

    
RotaryEmbedder按位置给出 cos、sin 表位置从 0 开始（位置 0 角度为 0）；cos²+sin²=1

    
RopeAttention投影 → 拆头 → 旋转 → repeat_kv → 注意力 → 合头K/V 只投影到 g·head_dim；mask 是加性的

  

  
RotaryEmbedder 的构造


inv_freq = 1 / base ** ( arange(0, dim, 2) / dim )        形状 (dim/2,)
angle    = outer( arange(S), inv_freq )                    形状 (S, dim/2)
emb      = cat([angle, angle], dim=-1)                     形状 (S, dim)   ← 前后两半用同一组角度
cos, sin = emb.cos(), emb.sin()                            再补成 (1, S, dim)

  
把同一组角度拼两遍，是为了和 rotate_half 的“前后半段配对”对上：第 i 维与第 i+dim/2 维共用一个角度。这也是判题里“同一个角度驱动一对分量”的含义。

  
RopeAttention 的形状流水


x                      (B, S, hidden)
q = q_proj(x)          (B, S, h·dh)   → view → (B, h, S, dh)
k = k_proj(x)          (B, S, g·dh)   → view → (B, g, S, dh)
v = v_proj(x)          同 k
旋转 q、k              cos/sin: (1, S, dh)  → 补 head 维 → (1, 1, S, dh)
k, v = repeat_kv(·, h // g)           (B, h, S, dh)
分数 = q @ kᵀ / sqrt(dh)              (B, h, S, S)
分数 = 分数 + attention_mask           加性：屏蔽处为 −inf，形状 (1,1,S,S)
权重 = softmax(分数)；输出 = 权重 @ v   (B, h, S, dh)
合头 → (B, S, h·dh) → o_proj → (B, S, hidden)

  
注意 mask 是加到分数上的，不是像 1.5 那样用布尔值填充。Hugging Face 的实现也是这种形式：softmax 在 float32 里算，再转回 q 的精度。

  
判题会检查什么

  

    
检查它在抓什么错

    
rotate_half 连用两次得 −x切分位置、符号写反

    
cos=1, sin=0 是恒等忘了把原向量加回去，或广播维度错

    
旋转保持向量长度一对分量用了不同的角度

    
repeat_kv 逐头原位复制用了整体平铺，把每个 Q 头配给了错的 K/V 头

    
RotaryEmbedder 在单位圆上、位置 0 角度为 0位置下标差一位

    
注意力对位置敏感根本没把旋转应用到 q、k 上

    
因果 mask 生效mask 加错位置、加在 softmax 之后

    
K/V 投影更窄（参数量少于 MHA）把 K/V 也投影到了 hidden

  

  
要想清楚

  
    
    
  1. 为什么 K 的头数少，旋转还能照常做？旋转只依赖位置和 head_dim，与头数无关；先旋转再复制，或先复制再旋转，结果一样，前者更省。
    2. 
    
  2. cos/sin 为什么不需要梯度？它们只由位置和 base 决定，没有可训练参数，所以 forward 用 @torch.no_grad()。
    3. 
    
  3. mask 为什么形状是 (1,1,S,S)？同一个因果 mask 对所有样本和所有头都一样，靠广播就够了。
    4. 
    
  4. 如果输入的 dtype 是 bf16，哪些地方要小心？cos/sin 的角度在 float32 里算更准，再转成输入的 dtype；softmax 在 float32 里算。
    5.

  • 已核对Hugging Face：modeling_llama.py （rotate_half、apply_rotary_pos_emb、repeat_kv、softmax 用 float32）
    • 
    
  • 已核对Llama 3：model.py （precompute_freqs_cis 的频率公式、repeat_kv）

3.3 组装完整的 SmolLM，并生成文本

  
把解码层堆起来，接上词嵌入和输出层，再写一个贪心生成循环。

  
先搭好脚手架

  
提交文件里需要有你前面已经通过的两块代码：1.4 的 RMSNorm，和 3.2 的整套 RoPE + GQA 注意力。把它们粘贴到文件开头，再完成下面这些新零件：

  

    
名字职责

    
SwiGLU(hidden, intermediate)三个无偏置 Linear：down( silu(gate(x)) * up(x) )

    
DecoderLayer(cfg)两个 RMSNorm + RopeAttention + SwiGLU，两处残差

    
SmolLM(cfg)embed_tokens、layers、norm、lm_head；可共享权重；forward(input_ids, labels=None) 返回 (logits, loss)

    
greedy_generate(model, ids, n)循环 n 次：取最后位置 logits 的 argmax，接到序列后面

  

  
属性名沿用 Hugging Face Llama 的命名，判题要用它们找到各个部件。

  
forward 的流程


1. 造加性因果 mask：(1,1,S,S)，上三角（不含对角线）为 −inf，其余为 0
2. x = embed_tokens(input_ids)
3. 依次通过每个 DecoderLayer：x = layer(x, mask)
4. logits = lm_head( norm(x) )
5. 有 labels 时：loss = cross_entropy( logits[:, :-1], labels[:, 1:] )   ← 错开一位

  
判题检查什么（共 9 项）

  

    
检查它在抓什么错

    
SwiGLU 形状与参数量带了偏置、少了 up 或 gate；写成了线性

    
forward 的形状与返回值返回格式不是 (logits, loss)；没 labels 时 loss 应为 None

    
loss 是 next-token忘了错开一位，让每个位置去预测自己

    
因果性改最后一个 token，前面位置的 logits 不能变

    
权重共享共享与否的参数量之差必须正好是 V·d

    
层是逐层堆叠的多一层增加的参数量必须相同（不能共用同一层）

    
残差连接把每层参数清零后，整个模型必须等于 lm_head(norm(embed_tokens(ids)))，即两处残差都在

    
所有参数都收到梯度某个子层没有真正参与计算（例如 SwiGLU 没用 up）

    
贪心生成输出前缀是原提示；每个新 token 是上一步最后位置 logits 的 argmax；结果确定

  

  
要想清楚

  
    
    
  1. 为什么 loss 要错开一位？位置 t 的输出要去预测位置 t+1 的 token，所以拿 logits[:, :-1] 对 labels[:, 1:]。
    2. 
    
  2. 共享权重在 PyTorch 里怎么写？让 lm_head.weight 指向同一个 Parameter：lm_head.weight = embed_tokens.weight。model.parameters() 会自动去重，所以参数量只算一次。
    3. 
    
  3. 生成时为什么要 @torch.no_grad()？不需要梯度，省显存。model.eval() 与它是两回事：前者关梯度，后者关 dropout 等训练行为。
    4. 
    
  4. 这个生成循环有什么低效之处？每一步都把整段序列重新过一遍，代价是 O(T²) 次前向。接上 2.3 的 KV cache，每步只处理新 token。
    5. 
    
  5. 贪心生成有什么问题？总选概率最大的，容易重复、缺乏多样性。采样（温度、top-k、top-p）在第 5 节讲。
    6. 
  

  
可选的延伸

  
    
    
  • 把 2.3 的 KV cache 接进 RopeAttention：记得新 token 的 RoPE 位置要用缓存当前的长度。
    • 
    
  • 数一数你的模型有多少参数，和 3.1 里的公式对一对。
    • 
    
  • 用很小的配置过拟合一小段文本，看 loss 能否降到接近 0。
    •

scikit-learn 的文档讲得很清楚：反复根据测试集调整超参数，会让“关于测试集的知识泄漏进模型”，评估指标就不再反映泛化性能。解决办法是再留出一份验证集：训练集上训练，验证集上选超参，最后只在测试集上评估一次。

怎么选超参数交叉验证；最后一次性在测试集上评估

A.1 评估指标

  
模型好不好，先看你问的是哪个问题。

  
混淆矩阵


             预测 0   预测 1
真实 0         TN       FP
真实 1         FN       TP

  

    
指标公式回答的问题

    
Accuracy(TP+TN) / 全部总体预测对了多少

    
PrecisionTP / (TP+FP)报“正”的里面，多少是真的

    
RecallTP / (TP+FN)真的正例里，抓到了多少

    
F12PR / (P+R)P 和 R 的调和平均，任何一个低都会拉低它

  

  
AUC

  
AUC = 随机抽一个正样本和一个负样本，正样本得分更高的概率（并列算 0.5）。它只看排序，与阈值无关。

  
不用画 ROC 曲线就能算：把所有得分排秩（并列取平均秩），则


AUC = ( Σ正样本的秩 − P(P+1)/2 ) / (P · N)      P、N 为正、负样本数

  
常见坑

  
    
    
  1. 类别不平衡时 accuracy 会骗人：99% 负样本，全猜负也有 99%。这时看 P/R/F1 或 AUC。
    2. 
    
  2. 没有任何预测为正时 precision 分母为 0，要约定返回 0.0，而不是 nan。
    3. 
    
  3. 得分并列时，直接 argsort 两次得到的秩是错的，要对相同得分取平均秩。
    4. 
    
  4. 阈值怎么选？降低阈值：recall 升、precision 通常降。按业务代价选，而不是默认 0.5。
    5. 
  

  
深入一层

  
1. F1 的零除约定。scikit-learn 的 f1_score 有 zero_division 参数，默认值是 "warn"：行为等同于返回 0，同时发出一条警告；也可以设成 0.0、1.0 或 np.nan（设成 nan 时，这样的值不参与平均）。本题的判题采用“返回 0.0”。

  
2. AUC 只看排序。roc_auc_score 的文档说明，目标得分可以是正类的概率估计，也可以是未经阈值化的决策值。所以 AUC 与阈值无关，也不要求得分是“校准过的概率”。

  
3. AUC 的定义。随机抽一个正样本和一个负样本，正样本得分更高的概率，并列时算一半：


AUC = P(s⁺ > s⁻) + ½ · P(s⁺ = s⁻)

  
它等价于 Mann–Whitney U 统计量，所以能用“排秩”一次算出（O(n log n)），而不必比较所有 P·N 个配对。

  
4. 什么时候看哪个指标。类别极不平衡时，ROC 曲线可能显得很乐观，因为假阳性率的分母是（很大的）负样本数；此时 PR 曲线（precision-recall）更能反映正类上的表现。AUC 高也不等于概率“校准”得好：校准关心的是预测 0.8 的样本里是否真有约 80% 是正类。

  
5. 多分类。把每个类别分别当作“正类”算一遍，再平均：宏平均（每类等权）、微平均（按样本汇总）。类别不平衡时两者差别会很大。

  
面试常追问

  
    
    
  1. precision 和 recall 的取舍，各举一个场景？垃圾邮件过滤更怕误杀（重 precision）；疾病筛查更怕漏诊（重 recall）。
    2. 
    
  2. 调高分类阈值，precision 和 recall 怎么变？通常 precision 上升、recall 下降。
    3. 
    
  3. F1 为什么用调和平均而不是算术平均？调和平均对较小的那个更敏感，任何一个很低，F1 就会很低。
    4. 
    
  4. ROC 曲线的横纵轴分别是什么？横轴假阳性率，纵轴真阳性率（即 recall）。
    5.

A.2 数据预处理

  
模型之前的那一半工作。

  
四个基本操作


标准化      z = (x − mean) / std            每列均值 0、方差 1
Min-Max     x' = (x − min) / (max − min)    压到 [0, 1]
独热编码    类别 → 长度为类别数的 0/1 向量
缺失值      数值列常用均值/中位数填充，类别列常用众数

  
什么时候用哪个

  
    
    
  • 基于距离的模型（KNN、K-Means、SVM）和用梯度下降的模型（线性/逻辑回归、神经网络）都需要把特征缩放到相近量级。
    • 
    
  • 树模型不依赖缩放。
    • 
    
  • 有极端离群点时，Min-Max 会被拉歪，标准化或中位数更稳。
    • 
  

  
最重要的一条：不要泄漏

  
均值、标准差、填充值都只能从训练集算出，再原样用到验证集和测试集。先在全量数据上标准化再划分，是最常见的数据泄漏。

  
常见坑

  
    
    
  1. 常数列的 std 为 0：除之前先处理，结果应为 0 而不是 nan。
    2. 
    
  2. 样本标准差（ddof=1）和总体标准差（ddof=0）差一点；题目没说就按 numpy 默认 ddof=0，并写在注释里。
    3. 
    
  3. one-hot 的列顺序必须确定：按排序后的类别排列，并允许外部传入 categories，保证训练和测试的列一致。
    4. 
    
  4. 填充时用 np.nanmean 忽略 NaN，否则整列均值都是 nan。
    5. 
  

  
深入一层

  
1. 标准差用哪个。scikit-learn 的 StandardScaler 用的是有偏估计，等价于 numpy.std(x, ddof=0)，文档还特别说明 ddof 的选择通常影响不大。本题与它一致。

  
2. 常数特征。scikit-learn 里有专门的 _handle_zeros_in_scale，作用是“把接近常数的特征的缩放系数设为 1”。因此常数列标准化后全是 0，而不是 nan。这正是本题判题的要求。

  
3. 防泄漏的标准写法。


scaler = StandardScaler().fit(X_train)       # 只用训练集学均值、标准差
X_train_t = scaler.transform(X_train)
X_test_t  = scaler.transform(X_test)         # 测试集用训练集的统计量

A.4 线性回归、岭回归与梯度下降

  
最基础的模型，也是最常考的“从零实现”。

  
模型与损失


ŷ = X w + b                 MSE = (1/n) Σ (ŷ − y)²

  
两种解法

  
解析解（正规方程）。给 X 拼一列 1 吸收截距，得到 Xb；令梯度为 0：


(XbᵀXb) θ = Xbᵀ y        # 用 np.linalg.lstsq 或 solve，不要手写求逆

  
梯度下降。每步沿负梯度走一小步：


e = X w + b − y
w ← w − lr · (2/n) Xᵀ e
b ← b − lr · (2/n) Σ e

  
岭回归（L2 正则）


损失 = ‖y − Xw‖² + α‖w‖²       （平方误差之和，与 scikit-learn 的 Ridge 一致）
解：(XbᵀXb + αI) θ = Xbᵀ y      （I 中对应截距的那一项设为 0）

  
α 越大，权重越小、模型越简单：方差降、偏差升。共线特征多时，正则还能让 XᵀX 可逆，解更稳。

  
偏差与方差

  

    
训练误差验证误差处理

    
欠拟合（高偏差）高高更复杂的模型、更多特征

    
过拟合（高方差）低高更多数据、正则、简化模型

  

  
常见坑

  
    
    
  1. 截距不要被惩罚；惩罚它等于强迫模型过原点。
    2. 
    
  2. 梯度下降不收敛时，先怀疑学习率太大或特征没缩放（A.2）。
    3. 
    
  3. w 的形状是 (d,)，b 是标量；返回顺序按题目约定。
    4. 
    
  4. 直接求逆 inv(XᵀX) 在共线时会爆，用 lstsq。
    5. 
  

  
深入一层

  
1. 先把岭回归的公式对齐。scikit-learn 的 Ridge 最小化的是


‖y − Xw‖² + α‖w‖²           （平方误差之和，不是均值）

  
对应的正规方程是 (XᵀX + αI) w = Xᵀy（带截距时 I 的对应项设为 0）。如果你的损失写成均值 MSE，那么等价的正则系数是 α/n。题目里的判题只比较“α=0 时与普通最小二乘一致”和“α 变大权重变小”，两种写法都能通过，但要和自己的公式保持一致。

  
2. 截距不被惩罚。scikit-learn 在 fit_intercept=True 时会先对 X 和 y 做中心化（内部调用 _preprocess_data），再解带惩罚的问题，所以截距不受惩罚。

  
3. 为什么 α>0 一定可解。XᵀX 半正定；加上 αI 后是正定的，必然可逆。当特征共线或样本数少于特征数时，普通最小二乘的解不唯一，而岭回归有唯一解。

  
4. 概率解释。假设噪声是高斯的，最小二乘就是最大似然；再给权重加一个高斯先验，得到的就是岭回归（最大后验）。

  
5. 梯度下降的学习率范围。MSE 的 Hessian 是 2XᵀX/n。学习率超过 1/λ_max(XᵀX/n) 就会发散。这就是为什么特征没缩放、量级差很大时，梯度下降很难调。

  
6. 评估。除了 MSE，还常用 R² = 1 − SS_res/SS_tot：它衡量模型比“始终预测均值”好多少。残差图可以发现非线性或异方差。

  
面试常追问

  
    
    
  1. 样本数小于特征数时，最小二乘会怎样？XᵀX 不可逆，解不唯一；用正则（岭回归）或降维。
    2. 
    
  2. L1（Lasso）和 L2（岭）的区别？L1 倾向产生稀疏解、没有闭式解；L2 收缩权重、有闭式解。
    3. 
    
  3. 多重共线性有什么表现？系数估计很不稳定，符号和大小随数据微小变化而剧烈变化；岭回归能缓解。
    4. 
    
  4. 为什么线性回归用 MSE？在高斯噪声假设下，它就是最大似然。
    5.

A.5 逻辑回归

  
线性模型 + sigmoid，二分类的基准线。

  
模型与损失


p = σ(X w + b),   σ(z) = 1 / (1 + e^−z)
log_loss = −mean( y·log p + (1−y)·log(1−p) )

  
梯度（值得背下来）


∂L/∂w = Xᵀ (p − y) / n  (+ l2 · w)
∂L/∂b = mean(p − y)

  
它和线性回归的梯度长得一样，只是残差变成了 p − y。这是 sigmoid 配交叉熵的结果。

  
数值稳定

  
    
    
  • sigmoid：z 很负时 e^−z 会溢出。分段写：z≥0 用 1/(1+e^−z)，z<0 用 e^z/(1+e^z)。
    • 
    
  • log_loss：先把 p 夹到 [1e-12, 1−1e-12]，避免 log(0)。
    • 
  

  
要想清楚

  
    
    
  1. 线性可分时，不加正则的权重会无限增大。L2 的作用之一就是让它有限。
    2. 
    
  2. 决策边界是 w·x + b = 0，是一条直线（超平面）。
    3. 
    
  3. 阈值 0.5 不是神圣的。类别不平衡或代价不对称时要调整。
    4. 
    
  4. 多分类怎么推广？softmax + 交叉熵（见仓库的 Softmax 题）。
    5. 
  

  
深入一层

  
1. 交叉熵从哪来。把 y 看作伯努利变量、概率为 p，对数似然是 y·log p + (1−y)·log(1−p)，取负号就是 log loss。再对 w 求导，因为 σ'(z) = σ(z)(1−σ(z)) 恰好与交叉熵里的分母抵消，剩下 (p − y)·x，非常简洁。

  
2. 数值稳定的 log loss。直接算 log(σ(z)) 在 z 很负时会下溢。用等价的写法（z 是 logit，y∈{0,1}）：


loss = max(z, 0) − z·y + log(1 + exp(−|z|))

  
它对任意大的 |z| 都稳定，深度学习框架里的“带 logits 的二元交叉熵”就是这样实现的。本题允许先算概率再 clip。

  
3. 正则化的写法差异。scikit-learn 的 LogisticRegression 用参数 C，文档说明它是“正则化强度的倒数”，更小的 C 意味着更强的正则，C=np.inf 即不正则。而本题的 l2 是直接作用在“均值损失”上的系数。若把目标写成“均值交叉熵 + (l2/2)·‖w‖²”，它与 sklearn 的 C 大致是 l2 = 1/(C·n) 的关系（这是我按常见的目标函数写法推导的，换算前请对照文档里的目标函数）。

  
4. 线性可分时。不加正则时，权重会一直增大让损失趋于 0，永远不收敛到有限值；加 L2 或提前停止可以避免。

  
5. 为什么分类不用 MSE。配合 sigmoid 时 MSE 不是凸的，且预测很错但很自信时梯度会饱和；交叉熵的梯度 p − y 在错得越多时越大。

  
面试常追问

  
    
    
  1. 决策边界是什么形状？w·x + b = 0，一个超平面。想要弯曲的边界，需要构造多项式/交叉特征，或换成非线性模型。
    2. 
    
  2. 类别不平衡怎么办？调类别权重、重采样、改阈值，并用 PR/AUC 评估（见 A.1）。
    3. 
    
  3. 多分类怎么做？softmax 回归（多项式逻辑回归），或者一对多（OvR）。
    4. 
    
  4. 输出的概率可信吗？不一定校准；需要时做校准（如 Platt scaling、等温回归）。
    5.

A.6 K 近邻（KNN）

  
没有训练过程的模型：预测就是“找最像的 k 个，投票”。

  
算法

  
    
    
  1. 对每个测试点，算它到所有训练点的距离。
    2. 
    
  2. 取距离最小的 k 个。
    3. 
    
  3. 分类：多数表决；回归：取均值。
    4. 
  


D = ((X_test[:, None, :] − X_train[None, :, :]) ** 2).sum(-1)   # (n_test, n_train)
nn = np.argsort(D, axis=1)[:, :k]                                # 最近 k 个的下标

  
比较远近只需要平方距离，不必开方。

  
要想清楚

  
    
    
  1. k 小：边界复杂、方差大，容易过拟合；k 大：边界平滑、偏差大。用交叉验证（A.3）选 k。
    2. 
    
  2. 必须缩放特征（A.2），否则量级大的特征会主导距离。
    3. 
    
  3. 高维下“距离”会失去区分度（维度灾难）。
    4. 
    
  4. 复杂度：预测 O(n_train · d) 每个点，数据大时需要 KD-tree 或近似最近邻。
    5. 
    
  5. 平票怎么办？约定一个确定的规则（例如取最小标签），否则结果不可复现。
    6. 
  

  
深入一层

  
1. 平票要显式约定。scikit-learn 的 KNN 文档里有一条警告：如果第 k 个和第 k+1 个近邻的距离相同但标签不同，结果会取决于训练数据的顺序。所以笔试里一定要照题目约定（本题是平票取最小标签），否则结果不可复现。

  
2. 加速结构。scikit-learn 的 algorithm 参数有 auto、ball_tree、kd_tree、brute。低维时树结构有效，高维时往往退化成暴力搜索。weights 参数可选 uniform（等权）或 distance（按距离倒数加权）。

  
3. 用矩阵乘法算距离。展开平方距离：


‖a − b‖² = ‖a‖² + ‖b‖² − 2 a·b      →  D = |A|²[:,None] + |B|²[None,:] − 2 A Bᵀ

  
这样不需要创建 (n_test, n_train, d) 的三维数组。数值误差可能让个别结果出现很小的负数，需要 clip(min=0)。n 很大时，即使是 (n_test, n_train) 的距离矩阵也会占很多内存，要按批处理测试点。

  
4. 高维。高维空间里点与点的距离常常变得相近，“最近”与“最远”的区别变小，KNN 的效果通常随维度升高而下降。先降维或做特征选择往往有用。

  
5. 回归版。对 k 个近邻的目标值取（加权）平均。

  
面试常追问

  
    
    
  1. k 取大取小各有什么后果？k=1 时训练误差为 0、边界很碎（高方差）；k 越大越平滑、偏差越大。用交叉验证选。
    2. 
    
  2. 二分类时 k 为什么常取奇数？避免平票。
    3. 
    
  3. 为什么 KNN 必须做特征缩放？距离被量级大的特征主导。
    4. 
    
  4. KNN 的训练和预测代价？训练几乎为零（只存数据），预测每个点要和全部训练点比较。
    5.

  • 已核对scikit-learn：neighbors/_classification.py （平票时结果取决于训练数据顺序的警告；algorithm 与 weights 参数）

A.7 决策树：找最好的一次划分

  
整棵树只是把“最好的一次划分”递归地用下去。

  
基尼不纯度


Gini(y) = 1 − Σ_c p_c²
纯节点 = 0；二分类各一半 = 0.5

  
划分的增益


Gain = Gini(父) − (n_L/n)·Gini(左) − (n_R/n)·Gini(右)

  
找最好的划分

  
    
    
  1. 对每个特征，把取值排序、去重。
    2. 
    
  2. 相邻两个不同取值的中点就是候选阈值。
    3. 
    
  3. 规则：x ≤ 阈值 进左子树，其余进右子树。
    4. 
    
  4. 选增益最大的 (特征, 阈值)。已纯或没法划分就返回 (None, None, 0)。
    5. 
  

  
也可以用信息熵 −Σ p log p 代替基尼；两者结果通常接近。

  
要想清楚

  
    
    
  1. 不限制深度的树能把训练集分到全纯：训练误差为 0，几乎必定过拟合。要用 max_depth、最小叶子样本数、剪枝来控制。
    2. 
    
  2. 树对特征缩放不敏感，能处理非线性和特征交互，但单棵树方差大。
    3. 
    
  3. 随机森林 = 许多棵在自助采样 + 随机特征子集上训练的树的投票，主要降低方差。
    4. 
    
  4. 梯度提升 = 一棵接一棵地拟合前面所有树的残差，主要降低偏差。
    5. 
  

  
深入一层

  
1. 默认准则。scikit-learn 的 DecisionTreeClassifier 的 criterion 可选 "gini"、"entropy"、"log_loss"，默认是 "gini"。

  
2. 树的几个固有特点。scikit-learn 的决策树文档里列出：

  
    
    
  • 树容易过拟合：生成过于复杂、泛化差的树，需要用最大深度、叶子最小样本数等机制来控制。
    • 
    
  • 树不稳定：数据的小变化可能得到完全不同的树，需要用集成方法来缓解。
    • 
    
  • 学习最优决策树被证明是 NP 完全的，所以实际算法是贪心的：每个节点做局部最优的选择，不保证得到全局最优的树。
    • 
  

  
3. 本题的朴素实现与高效实现。本题的参考写法对每个候选阈值都重新统计左右两边，总代价约 O(n²·d)。高效做法：对每个特征先排序，再沿排序顺序一边扫描一边累加各类别的计数，每个阈值 O(1) 更新，总计 O(n log n · d)。数据一大，这个区别就是能否通过时间限制的关键。

  
4. 回归树。把不纯度换成方差（MSE），叶子输出该叶子里目标的均值。

  
5. 集成。随机森林：在自助采样（bootstrap）和随机特征子集上训练许多棵树，投票/平均，主要降低方差。梯度提升：一棵接一棵地拟合前面模型的残差，主要降低偏差。

  
6. 特征重要性的一个坑。基于不纯度下降的特征重要性，容易偏向取值很多的特征（如 ID 类字段）。

    2. 
    
  2. 怎么防止过拟合？限制深度、最小叶子样本数、预剪枝/后剪枝，或者用集成。
    3. 
    
  3. 树对特征缩放敏感吗？不敏感，只依赖排序。
    4.

A.8 主成分分析（PCA）

  
找方差最大的方向，用更少的维度保留更多信息。

  
步骤

  
    
    
  1. 每列减去均值：Xc = X − mean。
    2. 
    
  2. 协方差矩阵 C = XcᵀXc / n，形状 (d, d)，对称。
    3. 
    
  3. 特征分解 C v = λ v，用 np.linalg.eigh（它返回升序，要翻转）。
    4. 
    
  4. 特征向量就是主成分，特征值 λ 就是该方向上的方差。
    5. 
    
  5. 取前 k 个：投影 = Xc @ components.T。
    6. 
  


解释方差比_j = λ_j / Σ λ
还原：X ≈ 投影 @ components + mean

  
要想清楚

  
    
    
  1. 为什么要先中心化？不中心化，第一主成分会被“均值方向”占据。
    2. 
    
  2. 主成分的符号是任意的（v 和 −v 等价）。判分时要用与符号无关的性质来比较。
    3. 
    
  3. PCA 对特征量级敏感：量级不同时，先标准化（A.2）。
    4. 
    
  4. 取满 d 个成分时应能无损还原；k 越小，信息损失越大。
    5. 
    
  5. 等价说法：对 Xc 做 SVD，右奇异向量就是主成分，λ = σ²/n。
    6. 
  

  
深入一层

  
1. 与 SVD 的关系。对中心化后的数据做奇异值分解 Xc = U Σ Vᵀ：Vᵀ 的行就是主成分，第 j 个主成分上的方差是 σ_j²/n（用 n−1 则是样本方差），投影结果是 U Σ（等于 Xc V）。scikit-learn 的 PCA 文档写明它用的是“数据的奇异值分解”，并且输入会被中心化，但不会按特征缩放。

  
2. 方差的分母。scikit-learn 的实现里有 explained_variance_ = (S**2) / (n_samples − 1)，即用的是 n−1。本题按 n 计算，只影响方差的数值，不影响解释方差比。

  
3. 符号是任意的。主成分 v 和 −v 是同一个方向。scikit-learn 在代码里专门用 svd_flip 对符号做约定（注释写的是“flip eigenvectors' sign to enforce deterministic output”）。这就是为什么本题的判题用“与符号无关”的性质（正交性、投影方差、重构误差）。

  
4. 重建误差。丢掉的那些特征值之和，就是平均重建误差的平方。取满 d 个成分则可以无损还原。

  
5. 选多少个成分。看累计解释方差比（例如保留 90%–95%），或看碎石图（特征值的下降曲线）的拐点。

  
6. 复杂度。对 d×d 协方差矩阵做特征分解是 O(d³)；当 d 远大于 n 时，可以改为分解 n×n 的 Gram 矩阵，或对数据矩阵直接做（截断）SVD。

  
面试常追问

  
    
    
  1. PCA 是监督还是无监督？无监督，只看特征的方差，不看标签。方差大不等于对分类有用。
    2. 
    
  2. 为什么先标准化？PCA 对尺度敏感，量级大的特征会主导主成分。
    3. 
    
  3. PCA 能处理非线性结构吗？不能，它是线性的；非线性可以用核 PCA、t-SNE、UMAP 等。
    4. 
    
  4. 主成分是怎么互相“正交”的？它们是对称矩阵的不同特征值对应的特征向量，天然正交。
    5. 
  

  
资料与核对

  
  • 已核对scikit-learn：decomposition/_pca.py （基于 SVD、输入中心化但不缩放、svd_flip 确定符号、explained_variance_ = S²/(n−1)）

A.9 pandas 数据处理

  
数据类题目的核心工具：分组、连接、填充。

  
常用操作


df.groupby("g")["x"].agg(["sum", "count"]).reset_index()   # 分组聚合
df.groupby("g")["x"].transform("mean")                      # 结果与原表等长，便于填充
df.sort_values("x", ascending=False).groupby("g").head(k)   # 每组前 k
a.merge(b, on="key", how="left")                            # 左连接
df["x"].fillna(value)    df.dropna(subset=["x"])            # 缺失值
df.copy()                                                   # 修改前先复制

  
要想清楚

  
    
    
  1. how="left" 保留左表所有行；右表没匹配到的列是 NaN。groupby 默认会丢掉分组键为 NaN 的行。
    2. 
    
  2. agg 返回的是以分组键为索引的表，要 reset_index() 才能让分组键变回一列。
    3. 
    
  3. transform 和 agg 的区别：前者保持原行数，后者每组一行。
    4. 
    
  4. 链式赋值（df[df.a>0]["b"] = 1）在 pandas 3.0 起永远不会生效，更早的版本里不可预测；统一用 .loc。
    5. 
    
  5. 能用向量化操作就别写 apply 加循环，慢几十倍。
    6. 
  

  
深入一层

  
1. transform 与 agg。pandas 的用户指南定义：transformation 是一种 GroupBy 操作，它的结果与被分组的对象有相同的索引（例如 cumsum、diff）。agg 则是每组一行。所以“用同组均值填缺失”要用 transform。

  
2. 分组键里的 NaN。指南写明：默认情况下，groupby 会把 NA 值从分组键里排除；想保留要传 dropna=False。所以左连接后没有匹配上国家的订单，在按 country 聚合时会被丢掉，这正是本题判题期望的行为。

  
3. 链式赋值。pandas 的指南写明：从 pandas 3.0 起 Copy-on-Write 是默认行为，这意味着链式索引赋值永远不会生效（即 df[df.a > 0]["b"] = 1 改不到原表）。在更早的版本里，它是否生效取决于内部是视图还是副本，行为不可预测。统一的安全写法是用 .loc：


df.loc[df["a"] > 0, "b"] = 1

  
4. 合并要检查行数。连接键有重复时（多对多），行数会成倍增长。合并前后核对行数，或使用 merge 的 validate 参数声明预期的关系（一对一、一对多等）。

  
5. 常见的笔试题型。


每组前 k      sort_values(...).groupby(g).head(k)      或 groupby(g)[v].nlargest(k)
去重          drop_duplicates(subset=[...], keep="first")
透视          pivot_table(index=..., columns=..., values=..., aggfunc=...)
滚动窗口      df[col].rolling(window).mean()
日期          pd.to_datetime(df[col])  之后用 .dt 访问年月日
缺失统计      df.isna().sum()

    2. 
    
  2. apply 为什么慢？它对每行/每组调用 Python 函数；能用向量化运算或内置聚合就不要用。
